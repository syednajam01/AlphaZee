# Phase G operations

Customer order access is granted by the 43-character code returned once by `POST /api/v1/orders` or by owner-assisted recovery. The code is stored as a SHA-256 hash. The customer should save it privately; the checkout confirmation shows it once. `POST /api/v1/orders/access` exchanges it for an order-scoped HttpOnly cookie (30 days). Codes expire after 180 days and can be revoked. Tracking, receipt upload, return submission, and exchange options require that cookie. Order number and phone never authorize access. Ten exchanges per order and 30 per client IP are permitted in a rolling 15-minute window; excess attempts return 429.

For a lost code or historical order, verify the customer through an independent owner-controlled channel, then use `POST /api/v1/admin/orders/{id}/access-recovery` with a meaningful `verification_note`. The response reveals a new code once; convey it through the verified channel. Use `POST /api/v1/admin/orders/{id}/access-revoke` to invalidate all existing codes and sessions for that order. Both owner operations require the normal owner session, Origin, and CSRF protections. Do not paste codes into URLs, analytics, or support logs.

A size exchange requires a delivered original order and a different active variant of the same product. Owner approval holds exact supplier stock and creates one zero-priced replacement line. Repeat approval is idempotent. The original item must be received and fully inspected before `POST /api/v1/admin/returns/{id}/dispatch-replacement` can dispatch. Replacement COD defaults to zero; an explicit `replacement_charge_minor` may be set during approval, separate from the original order total. Shipment status transitions use the existing `/admin/shipments/{id}/status` endpoint, including explicit received quantities for RTO. Inspect quarantined RTO units with `/admin/shipments/{id}/inspect-rto`; only accepted sellable units restock. The original order status and payment are unchanged by replacement delivery or RTO.
